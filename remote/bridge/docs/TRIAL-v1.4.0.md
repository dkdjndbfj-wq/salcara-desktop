# v1.4.0 试用说明：按需远程 / Codex 原生实验

> 历史技术资料，仅用于维护兼容实现；其中旧插件安装、授权和测试流程不是当前用户操作方法。普通用户请看 [最新使用教程](../../../docs/USER-GUIDE.zh.md)，不要按本页安装旧实验组件。

2026-09-30。源码与离线协议测试，不是生产部署或真实桌面验收报告。

## 试用顺序

1. 解压完整 Windows 软件包，运行 `Salcara Bridge.exe`，不要只复制单个 exe。
2. 在工具工作台的 Codex Desktop 卡片安装实验插件。已有旧 v0.1 插件请先卸载再安装。
3. 保存原 Codex 任务并自行重启；在一个独立控制对话中粘贴软件「复制授权指令」，确认原生工具授权。不要在这个控制对话本身测试发送。
4. 保持控制工具调用，最多 10 分钟。手机选择 Codex Desktop、确认 API，然后打开授权的原会话发送任务。到期可重新授权；「结束远程授权」只停远控，不停任务。
5. 电脑与手机需同站扫码配对；新服务器去重功能需 Hub 插件 0.3.0。提供的 `.s2plugin` 是**未正式签名的开发试验包**，未上传或部署，生产宿主可能拒绝直接安装。

本机 Android Studio 所配 SDK 目录已不存在，**未构建本次手机 APK**。手机代码已更新并定向测试，现有旧 APK 不会自动获得此功能；需安装 Android SDK 后原生构建或在正常开发环境构建。不要卸载已有手机应用以避免丢失本地资料。

## 省资源策略

- 启动普通手机应用只从本机恢复配对，不连接 Hub；查看远程页面、发送或刷新才使用短 HTTP 请求。
- 空闲会话没有定时请求；正在看的运行任务以 5→10→20 秒短请求更新。离开页面/后台暂停，网络失败退避至 60 秒。
- CLI 事件以序号继续读取，每页 100、一次最多 3 页；缓存窗口不够时重读原历史。Codex Desktop 使用原生会话快照，不将原生聊天持续上传服务器。
- 手机草稿和待确认发送内容按站点、电脑、会话保存在本机；凭证仍放 SecureStore，不放发送记录。未完整收到回执不能清空草稿。
- 同一消息始终使用同一个 requestId/operationId。新 Hub 在分发前写入无正文的私有去重记录，最多保留 24 小时；缓存与队列限量。Hub 重启/超时后未知送达只提示核对，不重新执行。
- 电脑仍保持一条轻量服务器待命连接用于跨 NAT 接收指令；这是待命中继，不是实时屏幕投影。不能宣称零连接、零服务器开销或断网也能即时执行。

## 实验限制

Codex Desktop：仅固定已研究 Windows x64 宿主版本、明确批准的活动调用、真实宿主元数据与最多 20 个已有原会话。内部接口不是公开稳定协议。手机不能控制授权用的控制对话；不能新建原生聊天、停止桌面任务或代替电脑审批。

Claude Desktop：普通 Chat / Cowork 控制及自动切换第三方配置仍未实现。Claude Code 独立保留，不能冒充原桌面。

聊天回复、思考摘要、工具输出/diff 仅展示原生接口确实公开的内容。没有完整内部思维、完整子代理树、桌面文件树/编辑器及逐字段的耗时保证。

站点中继内容尚无端到端加密，管理员可以接触转发数据。只连接可信站点。不发送 API Key、私有网关描述符、备份或宿主内部日志用于反馈。

## 验证边界

离线测试使用假原生管道、临时安装配置和本机测试服务器。没有安装到真实用户 Codex 配置、连接真实原生管道、重启 Codex、调用上游付费推理、生产签名或部署到 Salcara.top。Windows 构建成功也不等于手机到原桌面端到端成功。
