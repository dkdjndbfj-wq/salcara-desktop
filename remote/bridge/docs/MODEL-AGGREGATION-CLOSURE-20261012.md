# 多模型目录、工具启动与回滚复核（2026-10-12）

本记录接续 10 月 11 日聚合审查。此前文档中的全量数字对应此前候选，不代替本文验证。工作树包含用户与其他任务的改动；本轮未提交、发布或部署，未修改手机代码。所有新增验证使用合成凭据和本机工具/HTTP fixture，不访问真实账号或付费推理。

## 用户可见行为

- API 编辑页可以读取上游模型，也可以逐行编辑完整模型 ID。手工编辑保存为手工目录；自动启动同步保留它，点击 API 中的显式读取会重新采用上游目录。按模型自动协议、显式接口类型设置继续可用。
- Codex 工作台、独立高级启动和 Claude Desktop 第三方 API 打开入口，在启动前进行最多 5 秒的模型 GET。打开设置弹层本身无需等待该请求。没有模型接口或暂时连接失败时保留原目录；401/403 不启动；明确成功的空分组清理旧目录并阻止本次启动。
- 不把 HTTP 200 的错误对象、缺少/null data、无效模型数组解释成成功空分组，避免误删手工目录。目录检查不发送生成请求。
- 原工具记住的模型不属于当前 API 目录时，使用当前目录首个允许的模型初始化；启动后仍在原工具中选择。未知名称有原生协议兜底；明确 wire 设置优先。模型名称推断并不能证明上游具有工具、图片或推理档位能力。
- Codex 模型菜单覆盖保留用户开关选择，刷新不会自动打开。Claude Desktop 关闭覆盖时恢复原菜单的模型/discovery 字段，保持新 API、原聊天身份和其他设置。
- 只修改 API 模型编辑相关区域及其异步行为，沿用既有样式。未重做普通界面、手机界面或动画。

## 本轮修复的边界

1. **迟到模型列表**：桌面探测序号与保存共享锁，序号检查、账号/目录快照核对与配置提交连续执行。保存、删除、再次探测使旧结果失效；删除记录不会让同 ID 的旧序号复活。未保存新账号不建立无限增长的探测记录。
2. **旧模型残留**：Key/地址/来源/协议或模型规则变化清理旧目录、工具模型/协议和远程待用模型；显式空数组/null 清空也有同样处理。目录刷新删除默认模型时同步清理失效选择。已运行的上游流不重放。
3. **手工目录**：`ModelsManual` 是目录所有权标记，不是上游权限。后台手机核验仍取真实目录，并与手工列表取交集；它不能靠编辑绕过模型规则，后台刷新不会覆写手工列表。API 中显式读取可以回到自动目录。
4. **跨工具协议**：A 卡片的协议不能被直接打开的 B 卡片继承；旧配置未写 protocol 时根据实际模型/wire 推断，Claude/Grok/DeepSeek 进入 Codex 时需经兼容网关。Claude Desktop 的兼容路由和原始 ID 都受同一 deny 规则约束。
5. **启动期间换选择**：冻结模型读取前的工具选择；只允许本次目录提交造成的失效模型清理。读取期间或等待退出期间改选 B、改覆盖选项或程序路径，会拒绝旧 A 的启动提交。读取后再次核对来源，避免将未经本次探测的新 Key 当作已探测来源。
6. **启动授权**：共享启动在写入后、进程启动前核对账号、目录、工具选择和进程授权；独立启动增加 `LaunchAuthorized` 最后校验与取消检查。独立旧兼容入口的回调不是操作系统 spawn 与任意外部配置编辑的跨系统原子事务；生产网关连接另有运行期租约防止旧进程继续取得新授权。
7. **失败回滚**：独立 Codex/Claude 准备、入口解析、数据目录准备、最终校验、取消或启动失败，恢复配置/凭据/模型目录及一并生成的备份副文件；共享 Codex 备份把模型目录纳入事务。原来没有文件的恢复为不存在。
8. **旧备份**：旧两文件 Codex 备份只有在目录缺失、没有 Bridge 指针时才能升级；存在同名目录或缺少所有权证据时拒绝覆盖。损坏 JSON 即使部分解出了正确条数也拒绝。用户 `models_cache.json` 不被删除。
9. **Claude 菜单恢复**：仅在当前配置匹配上次应用快照后恢复目录字段；退出时外部修改不会被覆盖。失败回滚保留切换前菜单和凭据，不删除聊天库。
10. **API 弹层异步**：读取/保存返回时核对原 DOM 和原表单值，关闭、换编辑对象或期间改 Key/URL/模型不会被迟到结果覆盖。保存完成不关闭后来打开的弹层；新增账号保存期间继续编辑，会保留已经创建的 ID，下一次保存更新该记录而非重复创建。

- `internal/config/accounts.go`、`claude_catalog.go`：手工目录字段、工具协议隔离、模型规则。

- `internal/hubclient/model_catalog.go`：目录失效入口、手工目录身份与远程核验。
- `internal/launcher/service.go`、`switch.go`、`defaults.go`、`models.go`、`claude_desktop_3p.go`：目录事务、空列表分类、原目录恢复和最后启动校验。
- `internal/toolcfg/catalog.go`：Codex 目录指针识别，保留用户原生缓存。
- `internal/console/web/app.js`、`workbench.js`：API 模型编辑、异步结果隔离、覆盖开关保持。
- 新增配置、控制台、启动事务、目录解析与 Node VM 回归；既有 UI 快照仅调整本轮被明确改变的模型行为，保留其他布局断言。

## 真实边界

协议转换、目录发布和模拟工具启动已在代码测试中覆盖；没有以真实 Codex/Claude Desktop 版本、真实上游模型及 Android 实机完成付费工具调用验收。不能将任意模型名出现于菜单等同于该模型支持全部 Codex 功能。

本轮菜单覆盖与 API 启动是电脑配置功能；它不会扩大既有原生桌面远控授权。Codex 原生桌面控制、CLI 续聊、Claude Desktop 本地历史及 Claude Code 执行仍按各适配器实际能力区分。当前不据此宣称原生桌面所有按钮、审批和停止都可以无条件远程控制。
