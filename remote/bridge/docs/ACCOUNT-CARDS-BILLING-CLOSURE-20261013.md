# 账号卡片、用量与清理复核（2026-10-13）

本文件记录本轮增量，不表示全部远程能力均已验收。未提交、发布安装包或部署服务器；未读取实际账号文件、密钥或用户会话，未调用付费模型。

## 最终界面选择

以用户最后确认的紧凑 API 卡片为准，替代中途的全库等高版：

- 普通 API 和本地 API 服务采用相同宽度、14px 内边距、7px 间距、348px 基础高度；这是最小高度而非裁剪高度，内容过长或主动展开时可增长。
- 反代账号恢复独立内容高度，不跟随 API 卡片或同排最高账号拉伸。套餐、实际额度窗口与必要操作保留。
- 普通 API 只展示一次地址。供应商余额、今日请求、今日 Token 分列；分组、当前倍率、已发生费用合并为一行。
- 已保存模型数量与唯一的加入／移出服务按钮同排。四个工具图标启动入口保留；本地 Codex 反代服务只提供 Codex / Codex CLI。
- 本地服务保留可用／加入账号数、在途请求、美元估算与套餐分组；分组列表有界滚动，主动展开成员后放宽高度，不裁剪成员操作。
- 官方额度的美元估算直接放在对应进度条上方，和剩余百分比并排；不硬编码所有套餐都有 5 小时窗口。健康账号只保留改名、额度刷新、删除等必要操作；恢复操作按状态出现。

主要文件：`internal/console/web/shell.css`、`app.js`、`codex-accounts.js`、`api-card-membership.js`、对应 `scripts/test-*.mjs`。

## 余额、分组、倍率与费用

- 账号美元估算见 [OFFICIAL-ACCOUNT-DOLLAR-ESTIMATES-20261013.md](OFFICIAL-ACCOUNT-DOLLAR-ESTIMATES-20261013.md)。金额是本机可观测调用的 API 等值，不是 ChatGPT 钱包或套餐购买价格。每个原生额度窗口独立计算，不将 5 小时和周额度相加。
- 普通 API 余额只采用供应商明确返回的账户余额；不会把订阅限额或 Key 配额伪装为全站账户余额。同站多把 Key 可以返回同一账户余额，但不同 Key 的请求、Token、来源缓存不能合并。
- 倍率读取 Sub2API 的 `/v1/sub2api/billing`，不从模型名猜。严格协议、重复字段、时区／峰值边界及短有效期校验；1.5 秒可选查询限时，不让倍率接口拖住已有余额数据。
- `actual_cost` 是上游已发生费用，展示时不再次乘倍率。当前倍率不是历史账单、图片价或所有模型专价的替代；本轮未实现每次调用时的全供应商计费规则快照，不能宣称精确还原所有实际扣款。
- 当前分组仅采用明确的 `group_name` / `group.name`。Sub2API 订阅响应在匹配已核实协议时可使用 `planName`；普通钱包未返回分组时不展示，不把“钱包余额”当分组。
- 分组和倍率是同一 Key 的两个独立接口观测，上游未提供共同 revision，不能称为原子快照。统一短 TTL，并在换 Key / sourceRevision 变化时拒绝旧结果。
- 分组名称做长度、控制字符与 HTML 转义校验；账单响应大小有界，不跟随跨站重定向，不发送真实凭据给无关域名。

## 默认命名与服务成员变更

- 未填 API 名称时，在本机根据站点域名生成名称，处理公共后缀、私有托管后缀、IP 与 localhost；不为取名字请求外网。用户显式名称保留，编辑未提供名称不覆盖旧名。
- 服务成员面板分别处理文本／图片用途，不暗中同时加入两个池，不自动启用服务或创建密钥。
- 新成员操作必须带账号来源版本与客户端策略版本；服务器在处理入口和 Store.Update 内两次检查。主账号、隐式空列表回退及最后成员需走明确编辑，不展示虚假的“已全部移出”。

## 按需显示的账号清理

- 按后端统一的 `Account.cleanup` 判定是否显示清理按钮；读取未完成、无候选或清理完后隐藏，不在前端猜状态。
- 被移出工作空间、明确账号不可用或授权失效，以及明确的账号权限拒绝、已核实额度耗尽可进入确认列表。
- 根据最后补充要求，网络、超时、429、5xx、一般刷新失败、无效响应以及无法辨别来源的 403 均不进入清理列表，也不使按钮出现。未查、单纯过期的旧额度或取消检查不当作失败。
- 首次 401 只作为恢复中的中间状态；有刷新凭据时，要在恢复后再次被拒绝或明确的永久刷新拒绝后才成立。整个读取→刷新→重试阶段均阻止清理；调用者取消、超时后迟到的响应不能把首次 401 升级成永久失效。
- 额度接口的 HTML/WAF 错误页、截断正文、正文读取超时、JSONP、重复字段、超大响应和歧义 Content-Type 不作为授权失效证据。正常、完整 JSON 401 的一次凭据刷新重试仍保留。
- 刷新凭据时不再从任意错误描述中搜索 `invalid_grant` 等字样。只有明确的归一化永久拒绝才退役刷新凭据；生产 Device 传输还核对 400/401、唯一 JSON 媒体类型、严格结构化错误码和有界正文。SDK 兼容层只解析固定依赖版本的准确错误封装，不依赖自由文本关键词。
- 明确权限受限或额度耗尽等可恢复候选默认不勾选，但用户可以明确选择清理；网络失败不是可勾选候选。
- 新候选携带不可解析的观察版本 `revision`。提交时再次核对身份、凭据版本和当前观察；恢复成功、替换账号、正在刷新／登录／重置的账号不被旧确认删除。
- 旧三字段请求仅保留原 needs_login 清理范围，不能绕过新版本校验扩大删除范围。
- 清理只撤销本机对应凭据与关联配置，不删除聊天、项目或供应商账号。先持久撤销，再清理配置；写入失败与重试沿同一确认快照处理。
- 打开确认列表后若最新结果已无候选，旧入口立即隐藏；更早开始的账号列表读取不能把按钮重新显示。更晚开始的权威列表读取仍可正常更新，不会被旧空预览覆盖。

主要文件：`internal/codexaccounts/cleanup.go`、使用量错误分类／观察版本、`internal/console/official_cleanup.go`、`codex-accounts.js` 及对应测试。
