# Bridge 远程恢复与图片存储

实现入口：`internal/hubclient/durable_*.go`、`attachment_durable.go`、`attachment_hub.go`。

## 执行防重

经过 Hub 或 Direct 真实身份校验、具有 UUID `operationId` 的 `session.start/send/continue/steer`、`desktop.session.send`、审批答复和压缩请求，在现有绑定、API 来源校验后先提交 SQLite 执行占用，再调用适配器。相同作用域、UUID、参数和来源可恢复已完成回执；未完成占用、参数冲突或来源变化返回 `command_delivery_uncertain`，不会重新执行。重启不会清空占用记录。

作用域区分 Hub 身份/手机绑定、Direct 配对。执行原文不进入账本，参数和来源只保留摘要；回执使用本地 AES-GCM 密钥加密。回执正文保留 7 天，清理后仍保留紧凑的防重记录。最多 100,000 条防重记录、32 MiB 加密回执正文，达到上限拒绝新记录，不通过删除未知执行记录腾空间。

这是“最多执行一次、未知结果待核对”的保证，不代表操作与第三方 Agent 之间实现了分布式事务。旧客户端没有 UUID 的请求、本机控制台以及未携带远程身份上下文的内部调用仍走兼容路径。

## 事件恢复

每次接受事件都向加密 journal 写入并同步 SSD；日志达到 16 MiB 时压缩为受 8 MiB 队列预算约束的快照。超大被拒事件仅保存会话缺口元数据。发送前持久保存冻结 `batchId` 和完整请求字节。HTTP 成功后保存出队结果；若成功回执丢失或进程退出，重启重发原批次，由 Hub 的持久去重确认。

日志尾部不完整时保留已确认记录，并触发历史恢复提示。无法保存执行占用时不调用 Agent；事件保存异常会保留内存队列并标记需要恢复历史。

### 电脑端状态与恢复入口

「手机远程 → 消息与恢复」显示本机消息保存是否就绪、待同步到 Hub 的进度条数、最近送达 Hub 的时间和需要核对原会话的提示。计数描述进度消息，不是运行中的任务数，也不代表手机已收到或任务已完成。「刷新状态」只读本机状态，「查看电脑对话」打开原有会话列表，不会重新发送任务。

Hub 连接状态实时更新；状态轮询与刷新只替换只读区域，不抹掉登记码、电脑名称或项目路径的草稿。断线时暂停展示配对二维码，重连后在其原有效期内恢复展示。结果未知时应先核对电脑上的原会话；不要以断网为由重复发送。

已有恢复数据却缺失 `payload.key` 时，电脑端保留原目录并拒绝生成替代密钥，远程耐久执行能力显示不可用。应从同一份备份恢复完整 `remote-store`，不要删除执行账本来恢复运行。消息写入失败显示「保存异常」，成功保存完整快照后才恢复正常提示；需要补齐的历史标记继续保留。状态接口不返回原始磁盘错误、私有路径、消息内容或凭据。

### Bot 绑定代次

注册及 SSE hello/heartbeat 的 `eventScope/eventScopeRequired` 来自已认证的 Hub。
同一绑定重启保持原代次；换绑改变代次。Bot 上传事件和图片必须携带原代次，
图片请求头为 `X-Salcara-Event-Scope`。冻结的 HTTP 批次和图片目录使用同一
scope；旧 HTTP 回执不能出队新批次。

重启恢复的队列代次只用于选择受保护的图片目录，不能充当已认证授权。
完成同代次握手后继续原批次；新代次清除旧私有队列、冻结请求和会话恢复
标记，只保留不含会话身份的全局缺口。图片装饰与入队、等待锁的命令、
来源授权获取及执行账本都会再次复核冻结代次；旧注册回执在队列锁内
核对来源，不能覆盖新绑定。

已启用事件代次的站点仍有待同步事件、具体会话恢复标记或队列图片时，
当前版本拒绝备用站点迁移，并保留原站配置、冻结批次和图片引用。需恢复
原站连接并完成同步后再切换。当前未实现跨站事件代次与图片目录的原子
迁移；空队列切换及旧版无代次迁移兼容行为保留。没有私有数据的全局缺口
标记不单独阻止切换。

## 图片生命周期

- 图片目录位于实际 `config.Store.Path()` 所属目录的 `remote-store/attachments/<身份摘要>/`，不依赖系统临时目录。
- 每图最大 8 MiB，每次输入最多 4 张；磁盘分片逐片保存，完成时流式 Base64 解码，不在内存收集整图分片。
- 全部手机绑定共用 256 MiB、1,024 个完整图片文件上限；上传分片共用 48 MiB、8 个上传上限。满额时拒绝新图片，不驱逐正在使用的图片。
- 未完成上传按最后一片活动时间 1 小时过期；普通完整图片 24 小时过期。每分钟清理，并在启动/新写入时检查。旧绑定目录也清理。
- 同一图片可绑定多个会话；读取与清理受同一锁保护。Agent 调用期间使用读取租约；未被 Hub 确认的队列图片由事件引用保护。释放最后一个保护后，过期图片才可删除。
- Hub 输出图片在发送包含该引用的事件前，经 `/bridge/blobs` 上传原始字节并核验回执。输入图片本地不存在时从同身份 Hub 下载、检查格式和大小、同步并原子发布后再交给 Agent。
- 上传使用原 `att_<32hex>` ID，同 ID 重试由 Hub 按内容去重。旧 Hub 返回 404 时保留原 Bridge 图片读取路径。Direct 不向 Hub 上传其图片。

图片文件是供 Agent 按路径读取的私有目录文件，**目前没有对图片文件内容进行静态加密**；加密覆盖事件日志与执行回执。密钥保存在同一用户私有配置目录，不能称为端到端加密，也不能防护已取得该系统用户权限的进程。清理仅处理应用生成的附件文件，不删除用户原始图片。
