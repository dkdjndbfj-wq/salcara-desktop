# Codex API 专用网络入口

控制台「Codex API 模式」的网络设置支持最多 16 个专用 IPv4 端口。默认访问范围为本机；选择局域网后监听 `0.0.0.0`，请求仍须来自本机或私有网络地址，并通过命名客户端 Key、当前进程授权、模型权限及账号准入检查。

专用入口提供 `/v1/models`、`/v1/responses`、`/v1/responses/compact`、`/v1/chat/completions`、图片生成/编辑及已支持的 Codex backend 路径。它不提供控制台、账号管理、价表管理和工具网关路由。控制台继续使用原本的本机端口。

端口留空时使用控制台挂载的历史本机 API 地址。专用端口不能与控制台端口重复；任一端口被占用时，整个新监听集合停止，已准备的其他端口会关闭，不终止占用端口的未知程序。

客户端连接主机支持 `127.0.0.1`、`localhost`，或本机当前的私有 IPv4 地址。控制台显示当前可用局域网地址。WSL 镜像网络可使用 localhost；WSL NAT 模式使用局域网范围和 Windows 主机地址。防火墙或 WSL 网络配置由环境决定，这个功能不修改它们，也不自动安装 WSL relay 或改写 WSL 中的 profile。

保存设置采用授权版本检查。旧面板不能覆盖较新的授权；设置保存失败或端口启动失败时，本次进程内的服务先保持停止。设置与 enabled 意图可持久化，运行租约不持久化，因此 Bridge 重启后需要重新点击启动。本次授权已经接受并返回首个上游事件的请求保留排空语义；旧监听连接不能在网络设置恢复为相同内容后获得新的监听绑定。

原生官方上游 WebSocket 使用固定 `wss://chatgpt.com/backend-api/codex/responses`、系统 TLS 验证、私有无环境代理拨号器和一个已选中的受保护账号。每次真实 turn 有独立上游连接，取消及 Runtime 关闭会释放连接和未读取的响应管道。握手重定向不跟随；首事件前的 401 只允许账号服务在同一个账号上刷新一次；部分输出后不回放。它保留标准 Responses 请求及加密 reasoning 历史，兼容 `response.done`，并将上游容量错误转成安全的错误事件。

本文件描述代码行为。当前验证使用合成本机 provider；真实官方账号、局域网另一台设备和 WSL 真机链路仍需单独验证，不能用端口监听或模型目录代替真实上游证明。
