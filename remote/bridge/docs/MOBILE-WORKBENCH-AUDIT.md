# 手机远程工作台：当前实现与数据缺口

> 历史技术资料，仅用于维护兼容实现；其中旧插件安装、授权和测试流程不是当前用户操作方法。普通用户请看 [最新使用教程](../../../docs/USER-GUIDE.zh.md)，不要按本页安装旧实验组件。

2026-09-30 v1.4.0。源码与离线测试，不是上线验收。电脑提供插件安装/卸载/复制授权指令/结束授权，手机不远程安装插件。

## 当前交互

检查中转站插件 → 扫码确认站点/电脑 → 选择 Agent、确认当前 API → 原会话列表 → 会话 / 活动。顶端只放一个灯，点击查看原因。多条站点+电脑记录可保存，一次激活一条；配对与模型 Key 分开，手机选 Agent 不改密钥或重启工具。

回复主线放会话，工具、命令、diff 和轮次放活动。Codex Desktop 使用明确授权的原会话读取/续聊实验通道，未真实端到端验收；CLI 独立保留。历史来源不是权限，缺能力不回退 CLI。

## 一个顶端灯，按需短请求

灯描述最近请求与执行通道能力，不表示常驻连接。空闲、隐藏页面或后台没有定时同步；正在看的任务 5→10→20 秒更新，失败退避至 60 秒。电脑保留轻量待命中继，CLI 累积文字默认 2 秒合并上传，最终回复、审批、任务边界保留。

断网保留本机草稿、待确认消息和已读内容，恢复后继续序号或原快照读取。有效回执才清草稿；新 Hub 以稳定编号去重，未知送达停止重发并提示核对，不重新创建任务。

| 分段 | 当前数据 | 不应推断的结论 |
|---|---|---|
| 手机 ↔ Hub | 连接、重连、HTTP/SSE错误、插件发现 | Hub 不可达时电脑和工具状态应为未知，不应全部报离线 |
| Hub ↔ 电脑 | device.online、lastSeen | 电脑在线不代表工具已授权或模型可用 |
| 电脑 ↔ 工具 | installed/version、CLI运行状态 | 安装了 Codex 不代表可控制 Codex Desktop |
| 工具 ↔ 模型上游 | 模型名、失败 notice/turn error | 上游 429/认证错误不等于远控通道断开 |

当前没有可用的分段 RTT/首字延迟数据。device.ping 的总请求耗时只能描述调用方→Hub→Bridge→返回的总往返；不可使用不同设备的 wall clock 相减，也不能称为纯 Hub↔电脑延迟。

## 数据与界面缺口

- 项目只有允许的目录和会话 cwd，没有手机项目文件树/编辑器。
- tool 事件可带路径、diff、命令输出和状态；缺结构化本轮文件汇总及磁盘最终写入核验。审批 diff 可能是拟修改，不能显示为已应用。
- Event 只有 ts，缺 turnId、startedAt、completedAt、durationMs；同 ID 完成更新还会替换运行事件，当前不能准确计算思考、命令或轮次耗时。
- Codex 已解码一些上游时间和 parentThreadId，但没有转发共享事件；Claude 子代理和 sidechain 还有过滤。现有子代理只作普通工具卡，缺父子树、各自状态/输出/耗时。
- reasoning 文本只能来自上游 summary/公开 content 或 Claude 公开 thinking。建议名称“思考摘要 / 工具公开文本”，缺失显示暂无数据，不声称完整内部思维。
- 计划/待办目前作普通工具卡，缺独立结构化任务面板。
- 手机没有电脑命名 Key 选择、工具重启、插件安装/卸载 UI 和命令。

## 推荐表达

聊天保留回复主线，活动折叠工具详情，不显示常驻多段链路面板。真实耗时、子任务关联缺失时不虚构监控信息。

消息确认建议分阶段：服务器接收 → 电脑接收 → 工具开始 → 输出中 → 完成；确认到哪一段才显示哪一段。断线保留输入草稿，不把请求已入队当作桌面已收到。

下一个实施阶段需要补真实遥测与身份关联协议，以及原生桌面能力授权验收。交互演示中的子任务、耗时和阶段确认都是提案，不能据此宣传已经接通。
