# Salcara Desktop 1.6.9

本版本配套 Salcara Android 1.8.6 与 Salcara Hub 0.5.6，重点修复手机远程在正常网络延迟下连接失败、恢复入口不清楚以及旧状态干扰当前操作的问题。

- **放宽身份检查的合理等待时间。** 修复中转站正常响应较慢时误报“无法验证中转站身份”的问题。身份检查仍验证签名、有效期、服务身份和入口归属；多个备用地址在重试时继续推进，避免始终卡在前几个地址。
- **完善相邻连接操作。** 为入口恢复、备用站检查、电脑登记及后台解除旧手机授权保留合理等待时间；后台清理保留原绑定代次，不影响新绑定。切站的目标网络检查不再持续占用停止和审批共用的锁，提交前仍核对当前授权、目标和任务状态。
- **登记和手机绑定显示实际状态。** 电脑登记失败时提供对应恢复入口；连接状态按当前电脑与中转站显示。重新登记后的电脑需要在手机重新扫码，不能把旧的本地配对记录当作当前服务器已绑定。
- **恢复操作更直接。** 直连错误不会被刷新清掉，API 设置读取失败可以原地重试。中转站、Bot、直连均能找到当前电脑及 API 设置；保留待切换草稿，迟到回包不能把旧表单应用到新连接。
- **停止与审批更可靠。** 慢历史读取不会占满停止和审批的处理容量。恢复原生任务前核对身份与可控制状态，执行前再次检查授权；结果未知的审批保留原操作编号，不能更换决定重复发送。
- **完善 Hermes 事件与配置切换。** 兼容旧审批、提醒等级及工具完成事件，避免后续消息被卡住；在电脑确认支持后，手机可以回答澄清问题。Windows 私有侧问文件保持原权限要求，同时修复已有正确所有者时保存失败的问题。

“打开 Agent”仍直接启动 Agent，不先读取会话列表。切换 API 不删除历史；Hermes 原会话仍绑定启动时的来源，使用另一 API 时保留草稿并提供新建入口。启动和继续对话仍依赖对应 Agent 的原生能力与电脑环境。

请求超时不等于操作未执行。确定尚未发送的登记会明确提示检查连接后重试；已经发出但结果未知的任务、审批和登记应先核对原结果，不自动重复执行。电脑重新登记后，请按页面提示重新扫码绑定手机。

保持既有最低兼容版本和发布签名身份。Windows 更新包继续使用原 Ed25519 签名，未配置 Windows Authenticode 证书。合成回归、构建及隔离安装检查不代表所有真实手机、网络和付费 Agent 场景都已验收。
