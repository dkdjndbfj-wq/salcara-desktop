# Salcara Desktop 使用教程

Salcara Desktop 是工具工作台，不是 Codex 或 Claude 的替代客户端。你保存 API，再为已经安装的 Agent 选择 API；日常对话、模型选择和项目操作仍在原工具里完成。

## 1. 安装和打开

从 [正式 Releases](https://github.com/dkdjndbfj-wq/salcara-desktop/releases/latest) 下载 `Salcara-Desktop-<版本>-win32-x64-setup.exe`。双击后按向导安装，从开始菜单打开 **Salcara Desktop**；桌面快捷方式和安装后立即启动可自行勾选。

默认位置是 `%LOCALAPPDATA%\Programs\Salcara Desktop`，仅安装给当前 Windows 用户，不需要管理员权限。程序内部仍显示 **Salcara Bridge**，这是兼容既有配置保留的应用名称，不是另一个产品。

便携版下载 `.zip`，解压到自己的专用文件夹，运行其中的 `Salcara Bridge.exe`。不要单独移动 exe，也不要把 GitHub 的 Source code 当运行程序。

关闭主窗口只是隐藏，App 可能继续在悬浮球或托盘里运行。要完全退出，请用托盘的退出菜单。安装、重装前先结束任务并退出旧 Salcara；安装器不会替你强杀 Agent。

## 2. 准备 Agent

打开 **环境**，查看已安装的 Codex CLI、Claude Code 和运行环境。支持的工具可按页面入口安装；Codex 桌面 App、Claude Desktop 仍需另外下载并安装。

回到 **Agent** 后，可看到 Codex 桌面、Codex CLI、Claude Code、Claude Desktop 的工具卡片。显示“未安装”的工具先完成安装，不需要为了使用其他卡片把所有工具都装一遍。

## 3. 添加 API

打开 **API 密钥**，添加一条记录：

- **名称**：自定义，如“日常开发”或“备用服务”。
- **服务商地址**：使用服务商给的 API Base URL，不是管理后台、充值页或 Hub 管理页。不要根据网页域名猜 API 路径。
- **API Key**：服务商签发的模型调用密钥。
- **服务商认证方式**：默认 Bearer；服务商明确要求 x-api-key 时再切换。
- **接口类型**：一般保留按模型自动；服务商明确指定时再选 Responses / Chat Completions / Claude Messages。

同一条 API 可以供多个 Agent 选择，没有“Codex 专属密钥库”。加载模型目录会请求服务商的列表接口，不生成聊天内容；接口访问是否额外计费取决于服务商，不承诺所有站点都免费。

API 在本机保存，不需要把 Key 输入 Hub 管理后台。真实配置含密钥和必要备份，不能当普通文件分享或提交 GitHub。

## 4. 为 Agent 应用 API

1. 打开 **Agent**，在目标工具卡片中选一条 API。
2. 打开配置弹框，点击 **加载模型 / 重新加载**；Claude Desktop 使用 **刷新模型**。
3. 若希望工具菜单显示服务商目录，可启用 **覆盖 Codex 的模型选择栏** 或 **覆盖 Claude 的模型菜单**。
4. 确认原任务已经结束，再点 **打开**；Claude Desktop 点 **配置并打开**。
5. 在原 Agent 软件里选择模型，开始对话。

卡片选中 API 只是保存选择，最后点击打开才应用配置。Codex 桌面和 Claude Desktop 会重新打开原应用，不因换 Key 建立新的用户目录；CLI 则在终端打开。转换模式需要 Salcara 保持运行。

换 API 时重复上述步骤，先结束任务，再应用新配置。上游更换了同一 Key 的模型分组时，重新加载模型并在原工具里选择当前可用模型。列表里存在某个模型，不代表它支持全部编程工具功能；不兼容时检查接口类型、工具调用能力和服务商限制。

### Claude Desktop 第三方模式

Claude Desktop 使用官方第三方配置路径。首次接入可能切换到第三方模式；原账号聊天不会删除，但标准账号和第三方模式的可见聊天列表可能不同。之后更换 API 沿用同一第三方聊天库。

受组织策略管理或版本不兼容时会拒绝覆盖，不要强行编辑受管配置。转换模式下同样需要 Salcara 运行。卡片的 **⋯ → 恢复原配置** 可恢复之前的配置并重启 Claude；恢复标准模式后再查看原账号聊天。

## 5. 已有会话与恢复

支持的本机编程记录保留在原工具的数据目录，换 API 不删除项目或会话：

- **Codex / Claude Code**：卡片 **⋯ → 恢复会话**，选择已有记录，在原 CLI 继续。
- **Codex 桌面**：卡片 **⋯ → 用 CLI 恢复会话** 是命令行恢复，不等于桌面原生恢复。
- 支持的 Codex 对话页可用 **在 Codex 中打开** 请求桌面导航；已打开窗口未刷新时，需要重新打开对话，必要时重启原应用。
- **Claude Desktop**：其 Code 编程会话可由 Claude Code 后端继续；普通 Chat / Cowork 不支持手机直接发送或停止，也不是完整云端聊天备份。

正在运行的会话不能同时重复恢复。CLI 恢复前，应先为对应 CLI 应用要使用的 API，不要留下待应用的配置变更。恢复失败时先检查工具是否安装、项目原路径是否还存在、原进程是否仍在执行任务；不要通过删除原工具的数据目录来处理。

## 6. 手机远程（可选）

只在电脑用 Agent 可以跳过本节。远程需要兼容的 Salcara 手机 App、已部署的 Hub，以及保持在线的电脑。

1. 在桌面 **手机远程** 输入部署了 Hub 的 HTTPS 站点根地址，点击 **连接**。自定义 Hub 路径按部署者给的地址设置。
2. 连接成功后点击 **显示二维码**。
3. 手机进入 **编程**，按绑定电脑入口连接同一站点并扫描二维码。二维码五分钟有效、只能使用一次，不要公开分享；过期后重新生成。
4. 在电脑添加允许远程使用的项目文件夹。手机选择这台电脑、Agent 和电脑保存的 API，再选择会话续聊或创建编程任务。

不需要把 Hub 的管理员密钥当模型 API Key。普通设备配对不要求后台逐个审批，但 Hub 管理员仍可封禁设备。换另一台 Hub 时应重新连接配对，不能沿用旧站点的授权。

电脑关机、休眠、Salcara 退出，或者 Hub 不可达时，远程不能立即执行任务。连接恢复不等于所有旧任务必然可重放，过期/失败任务应在手机核对状态后再操作，避免重复提交。

手机续聊会写入支持的原会话记录，但**不是实时桌面镜像**：原 Codex / Claude 窗口可能需要重新打开会话才显示新内容。Codex 原生能力与版本相关；Claude Desktop Code 通过 Claude Code 继续，普通 Chat / Cowork 只在兼容本地库可读时提供记录查看，不提供发送/停止。

Hub 不是端到端加密服务，站点运营者可能接触中继内容。只连接可信站点，保持 HTTPS，不把本机控制台直接暴露到公网。

## 7. 更新

打开 **设置 → 版本更新 → 检查更新**。发现版本后按现有窗口下载，任务结束后选择重启并更新。签名、平台、大小和 SHA-256 不匹配时会拒绝安装；任务或审批未处理完也会拒绝退出。

1.6.4 起每 2 小时自动检查。弹出更新提示或下载文件不停止任务，也不会自行重启安装。1.6.1 / 1.6.2 内置更新失败时，请退出 Salcara 后手动运行 1.6.4 安装包一次，不要删除 AppData；卸载后留下的更新缓存由新版安装器兼容处理。

早期没有更新通道/公钥的开发版第一次需手动安装。1.6.0 便携版可以自动升级应用，但不会自动注册 Windows 安装记录；要获得快捷方式和卸载入口，退出旧便携版后运行 setup 即可。

手动重装前不要自行删除 AppData。用较旧 setup 覆盖已更新的新版本会被拒绝，改用当前正式版本。

## 8. 卸载与数据

先结束任务并从托盘退出 Salcara，再到 Windows **设置 → 应用 → 已安装的应用 → Salcara Desktop → 卸载**。

卸载只清理 Salcara 安装程序拥有的文件和快捷方式，不删除 API 配置、配对数据、原 Agent 的项目/聊天，也不卸载 Codex 或 Claude。便携版没有 Windows 卸载条目，完全退出后可删除自己的完整便携目录。

如果需要撤销某条 API 的访问权，请到服务商撤销 Key；从 Salcara 列表移除记录不等于已经运行的工具忘记了凭据。交出电脑前请另行处理敏感本地数据，不要将“卸载保留配置”理解为安全擦除。

## 9. 常见问题

| 情况 | 检查 |
| --- | --- |
| GitHub 只看到源码 | 打开 Releases 的 Assets，下载 setup 或便携 ZIP |
| 选择 API 后还没切换 | 结束原任务，在打开弹框中完成应用和打开步骤 |
| 模型列表为空 | 检查 API 地址、密钥权限和列表接口；不是 Hub 登录问题 |
| 401 / 403 / 额度不足 | 检查服务商后台，换有效 API；不要把 Key 发到 Issue |
| 关闭窗口后安装提示仍在运行 | 从托盘彻底退出，不要强杀正在工作的 Agent |
| 手机找不到电脑 | 确认同一 Hub、设备未封禁、电脑未休眠且 Salcara 仍在运行 |
| 电脑会话没立即显示手机回复 | 重新打开原会话；不保证原窗口实时刷新 |
| 卸载后重装仍能看到 API | 这是保留配置的预期行为，不是新的安装没生效 |

反馈时可提供系统/Agent/Salcara 版本、去敏错误和操作步骤。请勿提供 API Key、二维码、管理密钥、配对令牌或完整真实配置。
