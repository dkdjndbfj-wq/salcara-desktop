# Salcara Desktop 1.6.6

当前为发布候选准备稿，尚未公开发布。

本版本配套 Salcara Android 1.8.4 与 Salcara Hub 0.5.4，完善手机远程连接、Agent 启动、API 切换及项目选择。

- 打开 Agent 直接启动，不先加载会话或选择历史记录；对话记录保留独立入口。
- API 界面应用配置或应用并打开 Agent 时，先停止当前受管任务，确认停止后再切换。面板显示停止、应用和启动进度，避免重复提交；停止未确认时保留保护并提示原因。
- 切换 API 保留原有聊天记录、项目和文件。Hermes 旧会话保留原 API 身份，使用另一 API 需新建会话；其他 Agent 的继续能力遵循各自原生会话协议。
- 区分远程设备授权、手机配对与模型 API 凭据，完善自定义 Hub 路径、地址身份校验、来源切换和延迟响应处理。
- 手机可在 Code/Work 模式下不选文件夹创建独立工作区。工作区和启动回执持久保存，重复请求不会自动启动第二个任务。
- 手机可浏览电脑磁盘目录并创建项目。浏览不授予 Agent 目录权限；新建项目只授权精确目录，目录被替换或授权撤销后拒绝继续访问。
- 简化“加入 API 服务”的来源选择及追加流程，补充 Anthropic、Gemini、Ollama 原生协议适配。
- 优化桌面 Agent/API 卡片、近期记录加载和流式聊天状态；DeepSeek 历史可从原生记录分页读取，不再仅依赖最近 400 个事件缓存。

## 恢复与兼容边界

未知进程状态不会被当作已停止。未被 Bridge 可靠归属的外部 CLI、共享 Gateway 的未知任务及同次系统启动中无法确认的 DeepSeek worker，仍可能需要在电脑处理后再切换。Codex/Claude 的旧适配器内存保护不等于跨 Bridge 重启接管任意孤儿进程。Hermes 共享 Gateway 和原生历史读取仍受其原生能力限制。

DeepSeek 的持久保护与历史读取已完成专项验证；官方 SDK 启动初始化仍在发布前核验，不能将专项通过视为四种 Agent 的正式服务端到端验收。正式候选须通过同一源码的 Windows 打包和 Linux 检查后才发布。

本次保持现有最低兼容门槛。Windows 自动更新包继续使用已有 Ed25519 签名；尚未配置 Windows Authenticode 代码签名证书。实体手机、公网收费服务、macOS/Linux 安装包与 iOS 签名发行不在这些自动化检查的覆盖范围。
