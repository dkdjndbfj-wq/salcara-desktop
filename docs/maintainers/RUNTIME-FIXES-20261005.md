## 本轮完成

- Electron 最小化/关闭按钮走独立可信 IPC；项目目录选择走 Windows 原生目录选择器。
- 工具检测改为并行、短超时、按路径缓存和 singleflight；旧请求不能覆盖新页面。
- 手机绑定新电脑直接扫二维码，二维码内带站点地址；Hub 的配对状态通过同一 Bridge SSE 反馈。
- 单台电脑的物理手机绑定在所有已保存站点间共享；站点设备凭证仍各自独立。
- 配对成功后，Hub 在发送第一条手机命令前先发送 `pair.status`，避免首个会话读取与配对状态竞争。
- 配对请求有代际、attempt marker 和过期时间；Hub 重启会重新建立 revision 基线，旧快照不能恢复绑定。
- Bridge 对所有非 `device.ping` 指令都执行手机代际授权校验；不再使用可省略的 `Phone` 布尔字段作为授权开关。
- 会话读取复用 snapshot flight、恢复 cursor，短暂断线只重试只读请求；不会把局部会话错误误报成整条链路掉线。
- 通知仅限 Codex 中文最终回答的真实回合结束，并按 TurnID 去重。
- A→B 中转站切换：手机选择同一物理电脑的另一已配对站点时，先由 A 验证 B 的公开协议、设备凭证和手机代际，再提交站点切换；电脑先在 A 回执，随后重连 B。失败保留 A。API 与站点切换可通过 `remote.station.switch` 同一事务提交，API handle 使用同一 ComputerID 跨站稳定，但密钥始终留在电脑。
- 切换期间不创建新会话；B 使用保存的设备身份和原会话 key。已有任务、待确认消息、待回答问题或桌面实时租约存在时拒绝切换；手机端 API 切换也会检查整台电脑的两个 outbox，而不是只检查当前页面。
- 手机端为 A→B 写入不含密钥的短期切换意图；A 回执丢失、手机重启或 B 重连较慢时，会用 B 的独立设备凭证确认“同一台电脑已在线”，必要时恢复到 B。若 API/模型选择也在事务内，恢复前还会核对目标 Agent 的不透明 API handle 与模型，避免只因“B 在线”误认切换完成。
- 旧站点记录缺少 `computerId` 且两条记录复用同一 `deviceId` 时拒绝静默切换；必须更新电脑端并重新扫码，避免手机切到 B 而电脑仍停在 A。
- 修正不同站点使用不同 `deviceId` 时的切站判断：只要两条记录的 `computerId` 相同，手机仍会先请求电脑执行 A→B 交接，不会发生“手机已到 B、电脑还在 A”的假切换。
- A 已提交 B 但旧站回执在最后一步失败时，Bridge 仍会主动断开旧 SSE 并按新配置重连 B；同一切换操作的重试只接受相同的非敏感载荷，过期或不同载荷不会复用旧操作号。
- 手机切站增加连接代际保护：切换期间如果用户/系统已经选了另一条连接，不会让旧的异步结果覆盖新选择，未确认的交接意图会保留供下次恢复。
- 修正 POSIX/Windows 测试夹具的相对路径展示，避免跨平台路径把文件名显示成绝对路径。

## 本次 A/B API + 中转站交接补丁

- `remote.station.switch` 现在只接受严格 RFC 4122 UUID 操作号；交接前后都会检查待上传事件、恢复通知和 in-flight 前缀，且在目标站探测完成后再次检查，避免把 A 的事件尾部留在旧站。
- 交接前会检查 Codex 与 Claude 两个 worker family，而不是只检查手机当前卡片；任何一类仍在运行、等待审批或桌面实时租约存在时都拒绝切站。
- API 账号在网络探测期间若被电脑端修改，会在提交前用连接指纹再次校验；没有显式模型时会使该账号的已验证模型目录失效，避免把 A 的模型目录带到 B。
- Bridge 增加只读 `remote.station.receipt` 回执。手机在 B 上恢复交接时必须核对 operationId、payloadHash、Hub 地址和 deviceId；仅凭 B 在线、后来手动连接或 Agent 状态相同都不能误判为本次交接成功。
- 站点交接在队列锁下关闭新的上传批次：如果上传已经取得 in-flight 前缀则拒绝切换；如果切换先取得锁，flushLoop 会暂停，探测期间到达的迟到事件会让最终检查安全失败并留在 A，不会被静默丢弃或错发到 B。
- 进一步收紧提交后的授权窗口：B 的配置写入与最后队列检查在同一 `qmu` 临界区完成；提交后到 B 的 `pair.status` 到达前，事件只进入 B 队列，不会因暂时没有 B 的上传授权而被丢弃。B 授权后才放行上传；如果配对被撤销，则按未授权路径清理。
- 手机把“API + 站点”入口统一到同一个原子交接流程。电脑端 `agents.status` 仅在 API 地址与一个已保存站点同源且无歧义时返回公开站点元数据；手机只在该站点已配对、computerId 相同的情况下自动切站，否则保持 API 与 Hub 解耦，不猜测目标站点。
- 手机交接增加设备级互斥、连接代际检查、精确回执恢复；切换过程中 B 暂时离线时保留意图和 A 的重试路径。普通换 API 仍只换 Bridge worker，不强制更换 Hub。
- 远程读取新增的交接回执被列为只读命令，可在短暂断线时安全重试；写入任务、API 选择和审批回答仍不会自动重试。

## 仍需真实环境验收

- 交接前 A Hub 完全不可达是尚未完成的备用控制场景：远程切站命令仍经当前 A 投递，B 单独在线不代表电脑在 B 接收指令。已提交后回包丢失的恢复路径不能代替此能力；当前只能恢复 A 或由电脑本地改站，不能承诺手机无感灾难切换。
- 尚未在公网 A/B 两个真实 Hub、真实 Windows 原生对话框、Android 实机相机上做验收。
- 本次代码级验收未使用任何真实 API Key、Hub 密钥或服务器凭证；同源自动切站依赖电脑端已保存 B 站点、手机也已配对 B，若 API 与 Hub 使用不同域名，需要先在手机单独切换已配对站点再选 API。
- 旧 Hub 若没有 `attemptId` 会走兼容路径；新版 Hub 会严格校验 attempt marker。旧 Hub 不支持持久化命令回执时，A→B 切换失败不会自动重发，用户需重新选择目标站点。
- B Hub 离线时不会假装切换成功；电脑会先验证 B 的设备凭证和绑定状态，随后短暂重连。离线站点中已有的 Hub 缓存不能由电脑立即抹除，只能由 Hub 恢复后条件撤销。
- 同一物理电脑的 B 站点必须在电脑端预先保存，并且手机已经配对该站点；不会把任意手机或任意电脑的站点当成同一台电脑。
- A、B 可以为同一台电脑分配不同 `deviceId`。切换成功后，手机必须以 B 的 `deviceId` 重新读取 Agent/API 状态；原会话 key 仍保持不变。
- Hub 的新版单手机配对校验还覆盖了“撤销后新绑定代际尚未拿到 phone hash”的合法重绑窗口：活动绑定不能被空指纹请求替换，现代二维码没有 phone identity 也不会被消费。
